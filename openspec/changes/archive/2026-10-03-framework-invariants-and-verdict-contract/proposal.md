# Proposal

## Why

The framework's central promise is that one generic simulator runs any law with zero per-law code. Today that promise rests on discipline rather than construction: the artefact contract does not carry enough for a driver to be law-agnostic, so every consumer re-learns the law by hand. Five concrete gaps, all verified against the shipped artefacts.

**The ontology does not guarantee the driver's two anchors.** A driver needs citizens and time, but no law is obliged to declare either. `mayor-2027` and `mayor-quorum` declare `ph:Citizen` because they happened to, and encode the calendar as untyped integers (`ph:electionDay 10`) hanging off a Process individual with no GFO grounding. Nothing in the contract prevents a law that omits both, and the review gate cannot detect it: `check.py` asserts only that each `ph:` class has a GFO superclass and each `ph:` individual has `rdfs:label`, so a set missing the calendar contract passes vacuously.

**The calendar cannot be rendered without Python doing date arithmetic.** `law-framework` requires "Python never computes dates" and that the TUI resolve cycle names by IRI lookup, but no artefact carries a calendar epoch. `mayor-2027`'s manifest has `cycle_days`/`announce_minus` but no year; its ontology declares `ph:MayorElectionCycle` with no date properties and no cycle individuals, so "the Jan 2 announce duty" is unrenderable. Only `mayor-quorum` carries date-bearing cycle individuals, and each carries a single label (the election day) with announce and prepare left as relative offsets.

**An ECA's act parameters are declared nowhere.** To cast a vote the driver must emit `{"eca":"vote","voter":X,"candidate":Y}`, but the manifest declares only `id`/`eca_process`/`label`/`message`/`modality`, the verdict's `pending` is bare ECA ids, and the names exist only in Lean's `Act` inductive. The manifest's `message` placeholders (`{holder}`, `{citizen}`) do not even match the oracle's parameter names. The only working binding is hardcoded in `scripts/test_conformance.py:57`, which is per-law code in the one place that is supposed to be law-agnostic.

**The verdict contract is named after one process, and its witnesses are unstructured.** `VerdictData.wouldWin` is the election winner. Taxation and requisition laws have no winner, so the field is meaningless for them, and any law with a genuinely new result would need a verdict shape change — the framework-fixed contract is not actually fixed. Violation witnesses are worse: `law-framework` states the quorum failure reports a `{voted, total}` witness, but the compiled oracle returns null structured fields and conveys the counts only inside the English `detail` string, so nothing machine-readable survives. The same object holds three incoherent display stories: `violations[].detail` carries Lean-authored English, `pending` carries no display at all, and `wouldWin` carries a bare value.

**The world is modelled twice, which is why per-process schemas keep leaking.** The oracle reads a bespoke JSON state object while the consumer reads a knowledge graph, and nothing in the contract connects them — snapshot keys such as `day` have no declared counterpart in the ontology (`ph:electionDay` corresponds to no key at all). History is the sharpest symptom: `mayor-quorum` carries it as a bespoke `cycles` array inside the JSON object, while the consumer's graph would hold those cycles as ordinary individuals of the same class as the current one. Making the graph the snapshot removes the seam, so history and present become one kind of entity and a new process with an unfamiliar schema needs no new contract.

Underlying all four is that the framework is being shaped by two mayor laws, while its stated purpose is vastly different processes with divergent schemas. The fix is to make the artefact contract carry what a law-agnostic driver needs, so per-law freedom stops being something consumers must be told about.

**A fifth gap makes the rest unsatisfiable.** The ontologies declare zero object properties: no `hasParticipant`, no `hasSituationPart`, no `temporallyStartedBy`, no `roleIn`/`playedBy`, no `qualityOf`. What they hold is seven datatype properties and a list of classes, so `ph:MayorElectionCycle rdfs:subClassOf gfo-core:Process` inherits a category and attaches nothing to it — a process is a name, with no composition, participants, holders, bounds, or outcome. `prompts/onto-v1.md` already instructs "model BOTH `roleIn` and `playedBy`" and neither ontology contains either, because `check.py` asserts only class superclasses and individual labels and never examines object properties. This is also what blocks the graph work above: a ballot is a statement about two entities' relation, so a snapshot's `ballots` and `box` fields cannot become graph individuals without relations to express them. Three vestigial declarations follow from the same blindness: `ph:outcome` is declared and used by zero triples, all five `State` subclasses are declared and never instantiated, and `ph:DistributeBallots` is a Process class mapped to no ECA that no check in the repository can see.

## What Changes

- **BREAKING** Declare framework-invariant ontology classes every law must provide, GFO-grounded: `ph:Citizen` (`gfo-light:Object`; every individual carries `rdfs:label` and `ph:age`), `ph:Clock` (`gfo-light:TimeBoundary`; `ph:dayIndex` and `ph:atHour`, framework-fixed names, singleton), `ph:CalendarPoint` (`gfo-light:TimeBoundary`; `rdfs:label`, `ph:atDate`, `ph:dayIndex`, `ph:marksPhase`), `ph:CalendarSpan` (`gfo-light:Chronoid`; `temporallyStartedBy`/`FinishedBy` a `CalendarPoint`), and `ph:label` as a subproperty of `rdfs:label` for runtime individuals. `ph:atDate` becomes a subproperty of `gfo-core:dateTimeValue`; `ph:age`/`ph:atHour`/`ph:dayIndex` subproperties of `gfo-core:decimalValue`. Because `ph:Clock` and `ph:CalendarPoint` share `ph:dayIndex`, "current phase" is one type-driven comparison for any law.
- **BREAKING** The knowledge graph becomes the snapshot. `check` and `apply` exchange typed instance triples instead of a bespoke JSON state object, and the ontology's class declarations become the snapshot's schema. The graph carries the ongoing process instance and every historical instance of the same Process class, distinguished by `temporallyFinishedBy` rather than by an array-ordering convention, so history stops being a per-law special field. `apply` receives and returns the whole graph and replaces it wholesale, so the oracle's state and the graph never diverge. This is the change's largest single move and it is what makes divergent per-process state schemas a non-issue: there is one representation, and the ontology declares its shape.
- **BREAKING** The ontology becomes a frozen TBox: classes and properties are schema, individuals are runtime. Seed individuals move out of `ontology.ttl` into a sibling `population.ttl`, in the same RDF serialisation, so loading a seed needs no bespoke mapping. Runtime individuals accumulate in the knowledge graph (a triple store may replace it later without a contract change).
- **BREAKING** The calendar is a seed rather than a ceiling: a law SHALL be able to mint further `ph:CalendarPoint` and `ph:CalendarSpan` individuals into the runtime graph during simulation, so a process that schedules work at a moment not fixed when the law was reviewed still has a displayable calendar. Minted individuals carry the same declared properties as seeded ones and their dates are computed only by Lean. This was found to be necessary while working through a law that halts an election mid-span and postpones it — a case that needs a new date the frozen calendar cannot contain.
- **BREAKING** Generalise the verdict's result channel: `wouldWin` is replaced by a generic `readings` list of typed entries (`kind` in a closed set `decimal`/`ref`/`flag`), so any law reports its results without a new verdict field, and `phase` stays top-level. Violations gain a structured witness — individuals that break a quantified condition under `refs`, counts that fell short under `counts` — replacing flattened per-law witness fields; `detail` is retained for display. `pending` entries carry parameter slots with the choices available at that instant.
- Manifest v2: per ECA add `params` (name, ontology `role`, and a `source` from a closed set `selected`/`choices`) and `holder_role`; add a `readings` block giving each reading id, ontology class, label, and display template. The manifest remains the single declaration site the driver reads, and every declared `role` is validated against the ontology.
- Close the review gate. `check.py` gains structural checks for the framework invariants, grounding checks over relationship declarations, reachability and orphan checks over the declared hierarchy, calendar-coverage checks, cross-validation of manifest `eca_process`/`holder_role`/`params[].role` against ontology Process and Role classes and against `oracle list`, a subject-monotonicity property test over every ECA, a graph round-trip check, and a clock-totality test over absurd `day`/`hour` inputs.
- **BREAKING** Declare the relationship vocabulary every law may use, each as a grounded subproperty of its GFO counterpart: `ph:hasPhase` over `gfo-core:hasSituationPart`, `ph:hasParticipant`, `ph:hasTime` over `gfo-core:timeOf`, `ph:relates`/`ph:containsRole`, `ph:qualityOf`, and `ph:causedBy` over `gfo-core:causedBy`, with roles related by `ph:roleIn`/`ph:playedBy`.
- **BREAKING** The generated ontology declares the process hierarchy: each Process class names its constituent phases through `ph:hasPhase` as class-level assertions, every declared phase is marked by a `ph:CalendarSpan`, and every Process class is reachable from a declared root. Lifecycle bounds take GFO's shape — an instance relates to a `Chronoid` by `ph:hasTime`, whose `temporallyStartedBy`/`temporallyFinishedBy` point at `TimeBoundary` individuals — and absence of a start bound is what denotes an instance that has not begun.
- **BREAKING** The five `gfo-core:State` subclasses stop being vestigial: `RegistryOpen`, `BallotsReady`, `PollsOpen`, `PollsClosed`, `ResultsPosted` are the vocabulary a process moves through, and a law adds its own. This also makes the verdict's `phase` resolvable by IRI rather than a law-chosen string.
- **BREAKING** The rule-truth fence is drawn between structural and evaluated causality. No ordering relation appears between phases: they overlap, so a chain would assert something false and calendar bounds already answer ordering and overlap. A `ph:causedBy` MAY connect a `gfo-core:State` to a Process, stating that the situation the State holds *can* bring about a change — readable structure. Whether the State actually holds, and so whether the change fires, is evaluated only by the Lean guard. Nothing in the artefacts asserts that a dependency has fired.
- **BREAKING** No transition removes an individual from the graph. Once a vote is cast or a ballot delivered it persists; what a later rule may affect is only how it is counted. The gate asserts this as a property, applying each ECA in turn and confirming every prior subject survives, rather than as a policy statement. Both shipped oracles already satisfy it.
- **BREAKING** Each `pending` entry names the process instance its duty belongs to, so duties on concurrently unfolding processes are distinguishable and an act can name the one it acts in. Where a process type has several ongoing instances the act targets one through a parameter sourced from `choices`.
- Rewrite `artefacts/README.md`, whose documented verdict schema matches neither the compiled oracle nor the new contract (`would_win` vs `wouldWin`; nested `witness` object vs flattened `witnessCitizen`/`witnessCandidate`; `check [file]` argument undocumented). Its recorded risk — "witness schema varies per law" — also describes a variance that does not exist between the shipped laws and is not what needed fixing; witnesses were unstructured, not varying.
- Bump the generation prompts to v2 for the new contract, and re-freeze both artefact sets.

**Deliberately not changed:** no framework fallback-authority rule. Who holds a duty when no office is filled is decided inside each law's `rules.lean` — oldest, youngest, or otherwise — and the driver reads holders from `pending` without computing them. The framework also declines to require every law to distinguish a time-scoped phase from a stateful per-occurrence entity: both are Process instances, differing only in cardinality and nesting.

**Deliberately not changed:** no `tick` oracle verb. The driver writes `ph:Clock` directly because advancing time is a simulation control rather than a rule, and a cold subprocess spawn on the most frequent interaction would be a latency regression. The cost is that the clock becomes untrusted Lean input, which is why totality becomes a gate obligation.

**Accepted for now:** `apply` round-trips the whole graph rather than a delta, because the framework cannot know in advance what a law needs to decide; each law's conditions select what matters. The cost is that a long-running law's graph grows and every check grows with it. This is a deliberate deferral, not an oversight — the round-trip semantics are fixed now so a delta protocol can be layered on later without changing the contract.

## Capabilities

- **Declare the relationship vocabulary every law may use, each as a grounded subproperty of its GFO counterpart rather than a reuse of the GFO property directly: `ph:hasPhase` over `gfo-core:hasSituationPart`, `ph:hasParticipant` over `gfo-core:hasParticipant`, `ph:hasTime` over `gfo-core:timeOf`, `ph:relates` and `ph:containsRole` over `gfo-light:Relator`, `ph:qualityOf` over `gfo-light:qualityOf`, and `ph:causedBy` over `gfo-core:causedBy`. Roles become `roleIn`/`playedBy` as the ontology prompt already asks. Declaring framework subproperties follows the pattern the predecessor change set for `ph:atDate` and `ph:age`, so a reasoner can check the grounding and the gate can enumerate the hierarchy.
- The generated ontology declares the process hierarchy: each Process class names its constituent phases through `ph:hasPhase`, as plain class-level assertions rather than `someValuesFrom` restrictions, so the structure reads in a diff and can be enumerated by the gate. Composition is a statement about the shape of a process and holds no verdict, which is why it belongs in the ontology.
- Lifecycle bounds take GFO's actual shape rather than the shorthand. A process instance carries `ph:hasTime` pointing at a `Chronoid`, whose `gfo-core:temporallyStartedBy` and `temporallyFinishedBy` point at `TimeBoundary` individuals. Absence of a start bound is what marks an instance ongoing. `temporallyStartedBy` applied directly to a situation is not strictly typed and is not what a grounding check should accept.
- The rule-truth fence is drawn between structural and evaluated causality, rather than banning causal relations outright. No ordering relation SHALL appear between phases: they overlap, so a chain would assert something false, and calendar bounds already answer ordering and overlap from one source. A `ph:causedBy` relation, declared as a subproperty of `gfo-core:causedBy`, MAY connect a `gfo-core:State` to a Process, stating that the situation the State holds *can* bring about a change — readable structure, displayable by a guide before any check runs. Whether the State actually holds, and so whether the change fires, SHALL be evaluated only by the Lean guard. Nothing in the artefacts asserts that a dependency has fired; the graph and verdict record that.
- **No transition removes an individual from the graph. Once a vote is cast or a ballot delivered it persists, and what a later rule may affect is only how it is counted: when a finished process instance's outcome means its contributions do not count — an election stopped part-way through polling — the outcome SHALL record that without removing them. Erasure is not a power a law lacks by policy but one it does not have, so the gate asserts it as a property rather than a policy statement, applying each ECA in turn and confirming every prior subject survives. Both shipped oracles already satisfy this, so the rule records existing behaviour rather than constraining it.
- Each pending entry carries the process instance it belongs to, so duties group under parallel processes and an act can name the one it acts in. It rides the parameter mechanism the predecessor change introduces rather than adding a new act-envelope concept: a duty on a multi-instance process type takes a parameter sourced from `choices` over the open instances. This is untestable until a second process type exists, which is why it belongs with the hierarchy rather than in the predecessor.

### New Capabilities

None — the framework invariants are the existing `law-framework` contract, and artefact layout and gating are `law-extraction`. A new capability would duplicate both.

### Modified Capabilities

- `law-framework`: the ontology profile gains mandatory `ph:Citizen`, `ph:Clock`, `ph:CalendarPoint`, and `ph:CalendarSpan` with GFO time grounding and a calendar anchor carrying both a date and a Lean day index; snapshot identity becomes the knowledge graph with ongoing and historical process instances as the same kind of entity; the ECA metamodel gains declared act parameters and holder roles; the oracle runtime interface takes and returns the graph, replaces `wouldWin` with generic typed `readings`, adds structured violation witnesses and parameter slots to `pending`, and requires totality over untrusted clock values.
- `law-extraction`: the law variant layout gains sibling `population.ttl` for seeded individuals and becomes a TBox-only frozen schema; the machine-check gate gains structural invariant checks, manifest/ontology/`oracle list` cross-validation, a graph round-trip check, and clock totality.

## Impact

- `artefacts/mayor-2027/` and `artefacts/mayor-quorum/`: `ontology.ttl` reduced to a TBox plus GFO time and relationship properties and the declared hierarchy, new `population.ttl`, `rules.lean` reworked to derive state from instance triples with a framework-fixed `Citizen` record, plus the verdict/pending/witness shape, `manifest.yaml` v2 — both re-frozen.
- `prompts/onto-v2.md`, `prompts/manifest-v2.md` (v1 retained for audit), and `scripts/redraft.py` pointing at them.
- `scripts/check.py` (gate), `scripts/test_conformance.py` (loses its hardcoded `acts_for` parameter table; becomes parameter-driven), `scripts/snapshot_roundtrip.py`, `scripts/test_oracle.py`, `scripts/test_quorum.py`.
- `artefacts/README.md` protocol and verdict sections rewritten against the compiled oracle.
- `openspec/specs/law-framework/spec.md`, `openspec/specs/law-extraction/spec.md` via delta specs.
- Blocks `law-simulation-tui`, whose `design.md`, `tasks.md`, and spec delta predate the `eca-apply-transitions` breaking change and still assign transitions to Python; that change must be corrected to build on this contract rather than implemented as written.
