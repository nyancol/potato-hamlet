# Proposal

## Why

Two things the framework already asserts are not true of the shipped artefacts, and a third is true but nowhere written down.

`ph:Clock` is specified as the single carrier of the current position and as the framework-fixed input the driver writes. `mayor-quorum` does not read it. Its `snapshotOf` takes the position from each process instance's own `ph:dayIndex`, so writing the clock changes nothing, and the framework's own scenario — *"WHEN a consumer writes a new `ph:Clock` value into the graph and then calls `check` THEN the verdict reflects the new position"* — is false for that law and true for `requisitions`. The client compensates by writing time in three or four places, with a docstring conceding that the clock "is what the framework fixes" but is insufficient for a law keeping the day on the instance record. Meanwhile `writeBack` echoes the clock back from the *current process instance's* hour, so the oracle is a second writer on the same individual and clobbers the hour asymmetrically — `dayIndex` survives, `atHour` is zeroed — on the very act that mints a successor.

Minting is specified as a destination and a shape but not as a semantics. The specs say where minted individuals go, that they carry the declared properties, that their IRIs are deterministic, and that nothing is ever removed. What the implementation is, and what everything rests on, is unstated: the returned graph is the input graph extended by the canonical encoding of oracle state. Two consequences are missing. Re-encoding an individual whose value has not changed must emit nothing — otherwise the graph grows on every apply and a bound becomes unreadable. And nothing may exist only in Lean, or "the snapshot is the knowledge graph" is not true of the code. Determinism follows from both, and `design.md` already lists it as an open question that persistence depends on.

The freshness rule is stated too weakly to be useful. "IRIs SHALL be deterministic from `(case, index)`" reads as a recipe for fresh names, but its purpose is the opposite — content-addressing, so re-derivation collapses to a no-op. `requisitions` found this the hard way: keying a requisition IRI on the citizen alone made a second lodgement collide with a withdrawn first one, so the graph gained a start bound on an already-finished instance and the withdrawal was never recorded. The rule that fixes it — the key must include every dimension along which the fact can repeat — lives in a Lean docstring.

And the framework has no concept of an act that gives an existing individual a new meaning. `ph:relates` and `ph:qualityOf` are declared and grounded in GFO, and no `rules.lean` writes either. So a law cannot say that a sheet of paper comes to be a ballot during a preparation phase, nor that writing a name on it gives it that quality, because there is no declared way to express either. `applyPrepare` responds by creating forty `ph:BallotVote` individuals from nothing with `Ballot.mk owner cand true`, setting the delivered flag at construction. That is the framework permitting a world to gain objects out of thin air, and it has consequences: the intermediate state in which forty ballots exist undelivered is unrepresentable, which is why the missing-ballot witness can only report a count rather than name the paper that never arrived; and the paper, pen, and mailbox the law's duties refer to are declared classes that `population.ttl` seeds no individual of, so the law describes duties on objects the simulation does not contain.

## What Changes

- **BREAKING** — `ph:dayIndex` gains the `rdfs:domain gfo-light:TimeBoundary` that `ph:atHour` already carries. `ph:Clock` becomes the only individual holding the current position; a process instance no longer keeps a mutable position. This makes the framework's "the verdict reflects the new position" scenario true of every law, and makes "one local write" literally true of the TUI.
- **BREAKING** — the runtime advances the clock monotonically. Totality over absurd clock values is already required; monotonicity is what stops a backwards step from re-opening closed polls and admitting a vote into an election already counted and stamped void.
- Add the minting semantics the wire contract depends on and does not state: materialisation is stable (no triple for an unchanged individual) and total over the world (nothing exists only in Lean), which together make `apply` a pure function of `(graph, act)` and the graph a fold over acts parameterised by the clock.
- Replace "deterministic from `(case, index)`" with a freshness rule: a minted IRI is a function of the occurrence, not the holder, and a collision with an existing individual of a different encoding is an error rather than an overwrite.
- Declare which `ph:` properties are functional. The oracle's idempotence depends on it, the ontology currently declares none, and without it neither a law author nor the gate can tell a re-materialisation from a churn.
- Admit a relative calendar form. A span may carry `ph:gapDays` with no `ph:dayIndex` and no `ph:atDate`, because a phase due a fixed interval after a moment that exists only at runtime cannot be named absolutely at review time. `mayor-quorum` already ships one and the frozen artefact set passes; the requirement forbidding it predates the consequence.
- Reword "replacing it wholesale rather than merging into it". It describes consumer discipline correctly but reads as a description of the oracle, whose semantics is an extension of the input graph.
- Add the transformation semantics. An act may give an existing individual a new meaning rather than producing a new one: the meaning is a `gfo-light:Role` individual whose `ph:roleIn` names the process it holds in and whose `ph:playedBy` names the individual it is held by, so the same physical individual can hold a different role in each process it takes part in. What the act changes is what an existing thing is, and the qualities it acquires — the name written on a sheet — attach to that thing through `ph:qualityOf` rather than by minting a new carrier. An individual a law's duties refer to SHALL exist before the act that refers to it, and an act that would create a physical thing no seeded or previously minted individual accounts for SHALL be refused. Which role an individual holds in which process is a relation, not a type on the individual, so no individual changes its class as a process unfolds.
- Extend the review gate with checks for each of the above, so the properties are enforced rather than conventional: a subject carrying `ph:dayIndex` that is not a `TimeBoundary`; a non-functional property holding two values for one subject after an accepted act; a minted IRI colliding with a differently-encoded individual; an act whose declared inputs are not present in the graph; a role individual not relating to both a context and the individual playing it; an act sequence that leaves the graph alone reproducing every verdict.

**Deliberately not decided here:** whether a gap must name the anchor it is resolved against. The form is settled by the shipped artefact and by the reading that a law may leave a moment to the executor; whether the resolution must be *legible as such in the graph* rather than recorded only as the resolved point is open, and is recorded in `design.md` rather than asserted here. Also unchanged: no `tick` verb, no per-law code, and the `mints:` declaration stays a display affordance — under materialisation it cannot promise that an individual appears, only that one may.

**Deliberately left to other changes:** the shared physical vocabulary. That every law draws on one ontology of physical things — paper, pen, mailbox, box — is a separate change to `law-extraction` and to the framework invariants, because it decides what the framework requires of every law and therefore what a law author must seed. This change states only what an act may do to an individual that exists, so the shared vocabulary can be added on top without either depending on the other's shape. The rewrite of `mayor-quorum` that actually uses a transformation — sheets seeded, `prepare` split into making and delivering, the delivered flag becoming state — is a third change, since it changes that law's ECA list and its freeze, and `law-simulation-tui` is about to consume that list.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `law-framework`: the Nat-day time model gains a single clock, monotonic advance, and the relative calendar form; the ontology profile gains IRI freshness and the functional-property declaration; the oracle runtime interface gains the materialisation semantics and the rewording of the wholesale-replacement clause.
- `law-extraction`: "Machine checks before human review" gains the gate checks that enforce the above, including the totality check that the graph alone reproduces every verdict.

## Impact

- **Artefacts, all three cases.** `mayor-quorum/rules.lean` stops reading the position from its cycles and reads it from `ph:Clock`; its `writeBack` stops writing the clock. `requisitions` stops stamping a frozen clock reading onto each requisition. Both drop the redundant `ph:dayIndex` on a minted span, whose start is already named by its `temporallyStartedBy` bound. All three ontologies gain the `ph:dayIndex` domain; `law-extraction`'s prompt template must ask for it.
- **Client.** `OracleClient.set_time` and `set_cycle` collapse into `set_clock`, along with the "stays law-agnostic for the caller" hedge that papers over the split. `test_concurrency.py`'s clock-and-every-instance walk becomes a single write.
- **Gate.** `scripts/check.py` gains the new checks; `scripts/test_concurrency.py` and `scripts/test_cancellation.py` lose their per-instance time plumbing.
- **`mayor-quorum` does not yet comply.** Its `applyPrepare` still creates forty ballots out of nothing, which the transformation requirement forbids. The shipped law keeps working as it does and the gate's new checks are added in a way that reports it rather than failing the set, because making it comply is the separate `mayor-quorum` change. The requirement is stated now so that change has something to comply with.
- **The in-flight TUI change.** `law-simulation-tui`'s "the TUI SHALL own the clock as its only local state change" becomes true rather than aspirational, and it can implement against it directly.
- **No oracle protocol change.** No verb, no field, no new verdict key.
